Déroulement d'un tour de simulation
Schéma des événements SSE
red_action Action d'un agent Red — technique MITRE, cible, raisonnement LLM complet, résultat (success/blocked/detected), confidence
blue_response Réponse d'un agent Blue — alerte générée, techniques détectées, règles appliquées, recommended_response
alert Bannière d'alerte haute sévérité (CRITICAL/HIGH) dérivée des détections Blue — affichée prominemment dans l'UI
state_update Snapshot complet du réseau après chaque tour — état de tous les hôtes, scores Red/Blue, numéro de tour
game_over Fin de simulation — winner (red/blue), reason, final_scores, récapitulatif complet de la partie
heartbeat Keepalive SSE toutes les 15 s — maintient la connexion ouverte pendant les phases de réflexion des agents
Conditions de victoire
Red Team gagne si…
  • Le domain-controller passe au status owned
  • Chemin : web-server → workstation → DC
  • Exfiltration de données AD réussie
  • Avant le tour 20 (configurable)
Blue Team gagne si…
  • 3 tours consécutifs de détection complète
  • Tous les hôtes foothold/owned isolés
  • Red Team bloquée avant d'atteindre le DC
  • Score de détection > seuil configuré

Guide de déploiement
Dev local
docker-compose · 2 minutes
1
Copier .env.example → .env, renseigner GEMINI_API_KEY et GROQ_API_KEY
2
docker-compose up --build
3
Ouvrir http://localhost:5173
Clés API gratuites :
Gemini → aistudio.google.com/apikey
Groq → console.groq.com/keys
Production
Vercel + Render · gratuit
1
Push sur GitHub
2
Render : "New Web Service" → backend/, ajouter les env vars API keys
3
Vercel : importer le repo, root frontend/, ajouter VITE_API_URL = URL Render
4
Mettre à jour ALLOWED_ORIGINS backend avec l'URL Vercel
